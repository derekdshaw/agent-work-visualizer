# Plan 15.1: Rust version of the server

This plan writes the Go server again in Rust. The Rust binary must do the
same things as the Go binary: the same analysis, the same routes, the same
event stream, the same session logs, and the same files on disk. The web
page does not change. The page must not see a difference between the two
servers.

The Go code stays in the repository, and it stays the binary that the README
tells you to build. The Go binary is the reference for each check in this
plan. This plan does not remove the Go code.

The text uses Simplified Technical English (ASD-STE100). Code names, file
names, and commands are technical names. Do not change them.

## Depends on

Plans 01, 02, 08, and 15. These are the plans that change the Go code. Write
the Rust code from the Go code on `main` after they are merged.

The other plans change only `web/`. They can go before or after this plan.

## Pull requests

This plan is too large for one pull request. Each task is one pull request.
Do the tasks in sequence. Task 3 can be one pull request for each language.
After each pull request, `go build`, `go test ./...`, `cargo build`, and
`cargo test` must pass.

Run each `cargo` command of this plan in `backend/`, or add
`--manifest-path backend/Cargo.toml`.

Do not change the Go code while this plan is open. If a Go change is
necessary, make the same change in the Rust code in the same pull request.

## Decisions

- **Same behavior.** Write each Go function again in Rust with the same
  rules. Do not fix bugs or add features in this plan. Record each bug that
  you find, and fix it in a later plan in both languages.
- **Same names on disk.** The Rust binary uses the same paths as the Go
  binary: the session logs (`session.DefaultDir`), the settings file
  (`settings.DefaultPath`), and the Claude Code transcripts
  (`transcript.ProjectsDir`). It reads the session logs that the Go binary
  wrote, and the Go binary reads the logs that the Rust binary writes.
- **Same command line.** `agent-work-visualizer [ROOT] [--port N]`, with
  port 7777 as the default.
- **Folder.** The Rust code is in `backend/`, as the project standards say
  for a backend. `backend/` is one Cargo package with a library
  (`src/lib.rs`) and a binary (`src/main.rs`). The library lets the
  integration tests and `examples/dump_graph.rs` call the analyzer.
- **Modules.** Each Go package becomes one Rust module:

  | Go | Rust |
  | --- | --- |
  | `main.go` | `src/main.rs` |
  | `internal/callgraph` | `src/callgraph.rs` |
  | `internal/progress` | `src/progress.rs` |
  | `internal/analyzer` | `src/analyzer.rs` |
  | `internal/lang/langutil` | `src/lang/util.rs` |
  | `internal/lang/langtest` | `src/lang/test_util.rs` (`#[cfg(test)]`) |
  | `internal/lang/golang` | `src/lang/golang.rs` |
  | `internal/lang/java`, `python`, `rust`, `typescript` | `src/lang/java.rs`, `python.rs`, `rust.rs`, `typescript.rs` |
  | `internal/transcript` (`transcript.go`, `patch.go`, `bash.go`) | `src/transcript/mod.rs`, `patch.rs`, `bash.rs` |
  | `internal/transcript/transcripttest` | `src/transcript/test_util.rs` (`#[cfg(test)]`) |
  | `internal/activity` | `src/activity.rs` |
  | `internal/session` | `src/session.rs` |
  | `internal/settings` | `src/settings.rs` |
  | `internal/server` (`server.go`, `view.go`, `gate.go`, `roots.go`, `graph.go`, `web.go`) | `src/server/mod.rs`, `view.rs`, `gate.rs`, `roots.rs`, `graph.rs`, `web.rs` |

- **Crates.** Use the project standard stack. Add no other crate without a
  reason in the pull request.

  | Need | Crate |
  | --- | --- |
  | Parser | `tree-sitter` 0.25, the same core version as `go-tree-sitter` v0.25.0 |
  | Grammars | `tree-sitter-go`, `tree-sitter-java`, `tree-sitter-python`, `tree-sitter-rust`, `tree-sitter-typescript`, at the versions in `go.mod` |
  | HTTP and the event stream | `axum`, `tokio`, `tokio-util` (`CancellationToken`) |
  | JSON | `serde`, `serde_json` |
  | Times | `chrono` |
  | Regular expressions | `regex` |
  | Directory walk | `walkdir` |
  | Files that stay in the open folder | `cap-std` |
  | Web files in the binary | `rust-embed` |
  | Command line | `clap` |
  | Errors | `anyhow` |
  | Log lines | `tracing`, `tracing-subscriber` |
  | Tests | `tempfile`; `reqwest` for the HTTP tests |

- **Grammar versions.** A different grammar version gives a different
  tree, and thus a different graph. Before you add a grammar crate, find
  its versions with `cargo info <crate>`. Use the version in `go.mod`. If
  crates.io does not have that version, use the nearest one, and write the
  difference in the pull request. The graph check in Task 2 or 3 must still
  pass.
- **Parsing stays in sequence**, as in `EachFile`. Thus, the log lines come
  in the same order. Parallel parsing is a later plan.
- **Threads.** The server is async on Tokio. The analysis is CPU work, so it
  runs in `tokio::task::spawn_blocking`. Do not hold a `std::sync::Mutex`
  across an `.await`.
- **Go concurrency in Rust:**

  | Go | Rust |
  | --- | --- |
  | A goroutine with a `time.Ticker` | A `tokio::spawn` task with `tokio::time::interval` |
  | `context.Context` and `cancel` | `CancellationToken`; a child token for each view |
  | `sync.WaitGroup` of the view workers | `tokio::task::JoinSet` or a `TaskTracker` |
  | `waiters` and `wake()` in `view.go` | A `tokio::sync::watch` channel of the control sequence. A stream waits on `changed()`, so it does not lose a wake. |
  | The `edits` channel with a size of 1 | `tokio::sync::mpsc::channel(1)` and `try_send` |
  | `pauseGate.resumed` | A `tokio::sync::watch<bool>` |
  | `defer s.release()` | A guard type whose `Drop` releases the hold |

- **Errors.** Use `anyhow` with `.context(...)`. Keep the error text of the
  Go code where the page or a person reads it: parse errors, HTTP error
  bodies, and status events.
- **Log lines.** Keep the text of each Go log line. The time prefix can be
  different.
- **No `unsafe`.**
- **The Cargo package name regex** in the Rust analyzer
  (`cargoPackageName`, `rust.go:88`) stays a regex. Do not change to a TOML
  parser in this plan.

## Differences between Go and Rust to look for

Each row is a place where code that looks the same gives a different
result. Each row has a test in the task that contains it.

| Go | Rust | What to do |
| --- | --- | --- |
| `filepath.Ext(".bashrc")` is `".bashrc"`. | `Path::extension` of `.bashrc` is `None`. | Write `ext(path)` with the Go rule: the text from the last `.` in the base name. Test `.bashrc`, `a.d.ts`, and `Makefile`. |
| A Go string can hold bytes that are not UTF-8. | `Node::utf8_text` returns an error for them. | Read node text as bytes, and change it with `String::from_utf8_lossy`. Test a Go file with a byte `0xff` in a comment. |
| `json.Marshal` writes `<`, `>`, and `&` as `<`, `>`, and `&`. | `serde_json` writes them as they are. | Compare JSON after you parse it, not as bytes. |
| `json.Marshal` writes the float `12` as `12`. | `serde_json` writes `12.0`. | The page reads numbers, so this is correct. Compare parsed JSON. |
| `omitempty` drops `0`, `false`, `""`, and empty slices. | `serde` writes all fields. | Add `skip_serializing_if` for each `omitempty` field. Test the JSON of an event with each field empty. |
| A `nil` slice with no `omitempty` is `null`. | A `Vec` is `[]`. | Find each such field. Make sure that the page accepts `[]`. |
| `time.Time` is RFC 3339 with nanoseconds and the local offset. | `chrono` can write other forms. | Write RFC 3339 with the local offset. Read any RFC 3339 text. Test a header and an event from a log that the Go binary wrote. |
| The JSON decoder matches field names with no case. | `serde` matches the exact name. | Claude Code writes exact names. Test with real transcript lines from `transcripttest`. |
| `sort.Slice` is not stable. | `sort_by` is stable. | Use the same sort keys as `finish` (`analyzer.go`): bytes of the ID, and `%s:%09d:%s` for an unresolved call. Compare graphs as sets. |
| Map order is random. | `HashMap` order is random. | Where the Go code sorts before output, sort. Do not add a sort where Go has none. |
| `projectName` uses UTF-16 code units and a Java string hash. | `str` is UTF-8. | Use `encode_utf16()`, and the same integer width and wrap-around as the Go code. Write the tests of `EncodeProjectPath` again with the same values. |
| `os.OpenRoot` refuses a path that goes out of the folder through `..` or a symbolic link. | `std::fs` has no such function. | Use `cap_std::fs::Dir`. Write `TestServeFileStaysInsideTheFolder` again. This is a security check. Do not skip it. |
| The request context ends when the client goes away. | axum drops the handler future, but only when hyper sees that the connection closed. hyper does not always see this while a response waits. | Release a gate hold in `Drop`. Write `TestServeGateReleasesTheCallWhenTheClientLeaves` again. If the test fails, find the closed connection in another way. Do not change the test. |
| `http.Server.Shutdown` plus the base context ends open streams. | axum graceful shutdown waits for open connections. | End each event stream and each gate hold on the server token. Else Ctrl+C does not stop the server while a page is open. |

## Task 6: The server

### Result

- `main.rs` reads the command line with `clap`, registers the five
  languages, and calls `server::run`.
- `server::run` listens on `127.0.0.1` only, and stops on Ctrl+C or
  SIGTERM.
- The routes of `server.go` and plan 15, with the same methods, paths,
  status codes, content types, and `Cache-Control: no-store`:

  | Route | Notes |
  | --- | --- |
  | `GET /api/graph` | The stored payload bytes of the current view. |
  | `GET /events` | Server-sent events. See below. |
  | `GET /api/roots`, `GET /api/sessions`, `GET /api/sessions/{name}` | |
  | `GET /api/file` | Through `cap_std::fs::Dir`. 404 for a path out of the folder, 413 above 2 MiB. |
  | `POST /api/root` | 400, 409, and 422 as now. |
  | `POST /api/pause`, `POST /api/resume` | 204. |
  | `POST /gate` | The pause gate. See below. |
  | `GET /api/settings`, `POST /api/settings` | As plan 15. |
  | `GET /` | The web files. |

- **Host and Origin.** A layer in front of all routes does what the handler
  at `server.go:221` does. A host other than `127.0.0.1` or `localhost`
  gets 403 `unknown host`. A request that is not GET, with an `Origin` that
  is not `http://` plus the Host, gets 403 `cross-origin request`.
- **Event stream.** The same frames as `serveEvents`:
  - A log line is `id: N`, `event: log`, `data: LINE`, where N is its line
    number.
  - A control event has no `id`.
  - A stream starts with the latest control of each name, in sequence
    order.
  - A `view` query that is not the current log name, or a `Last-Event-ID`
    that is not a number or is past the end of the log, gets one
    `event: reset` frame with `data: {}`, and the stream ends.
  - The stream ends when the server stops.
- **Pause gate.** The rules of `gate.go`: hold only the sessions that the
  view follows, deny after `gateHoldLimit` with the same JSON, answer `{}`
  on resume or when the server stops, and publish `pause` with `waiting`.
  The guard releases the hold when the client goes away.
- **View workers.** `watch` (each 500 ms, a scan each 4 polls), `refresh`
  (2 s after the last edit), and `watchWorktrees` (each 10 s), as in
  `view.go`. `openFolder` stops the workers of the old view and sends it
  `reset`.
- **Git.** `gitBranch` and `worktreeRoots` run `git` with a 5 s limit, as
  now (`tokio::process::Command` with `tokio::time::timeout`).
- **Web files.** `rust-embed` embeds `../internal/server/web/dist`. Without
  `index.html`, every page request gets the 503 page of `web.go`. Only `/`
  and `/index.html` get `Cache-Control: no-store`.
  - The build must pass when the folder does not exist. Check how your
    `rust-embed` version acts on a missing folder. If it fails, set the
    option that lets the folder be missing, or make the folder in
    `build.rs`.
  - In a debug build, `rust-embed` reads the files from disk. Enable the
    `debug-embed` feature, so debug and release builds act the same.

### Tests

2. Write the test of `main_test.go` again for the accepted and refused
